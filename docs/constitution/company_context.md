# Company Context — 회사의 현실

_모든 임원이 회의 전에 읽는다. 전략은 이 조건 안에서만 유효하다._

이 문서가 있는 이유: 회의 #010에서 임원들이 "CEO 지인 20명에게 직접 판매"를 가결했으나,
CEO에게 50만원짜리를 제안할 지인이 없어 무효화됐다. **임원이 회사의 현실을 모른 채
일반론으로 결정하면 그 회의는 낭비다.** 사실과 다르면 CEO가 이 파일을 고친다.

_최종 갱신: 2026-07-28_

## 우리가 무엇을 만드는 회사인가 (CEO 지침, 2026-07-28)

**우리는 인간을 이롭게 하는 서비스를 개발한다.**

**아이디어는 사람이 느끼는 사소한 불편에서 얻는다.** 시장 규모나 트렌드에서
역산하지 마라. "이런 게 팔린다더라"가 아니라 "이게 불편하더라"에서 시작한다.
누군가 매번 참고 넘어가는 작은 성가심 — 거기에 제품이 있다.

**제품을 제안할 때는 반드시 이 두 가지를 먼저 답하라.**

| 질문 | 답이 없으면 |
|---|---|
| **누구의** 불편인가 | 그 사람을 특정하지 못하면 팔 곳도 없다 |
| **어떤** 불편을 없애는가 | 없애는 게 뭔지 한 문장으로 못 쓰면 만들 것도 불분명하다 |

**전자책은 특히 엄격히 적용한다.** 정보를 모아 놓은 것은 제품이 아니다.
"AI 활용법 100가지"는 제품이 아니고, "매주 일요일 밤 세 시간씩 수업 계획을 짜느라
지치는 홈스쿨 부모가 그 시간을 40분으로 줄이는 법"은 제품이다.
목차를 쓰기 전에 독자가 지금 무엇 때문에 힘든지부터 쓴다.

**금지**: 불편이 특정되지 않은 제품 제안. 그런 안은 표결에 올리지 마라.

## 지금 회사가 있는 단계

**아직 채널이 없는 단계다.** 이 순서를 건너뛰지 마라.

| 단계 | 상태 | 판단 기준 |
|---|---|---|
| 1. 채널 확보 | **← 지금 여기** | 게시물이 실제로 사람들에게 도달하는가 |
| 2. 신뢰 축적 | 미착수 | 우리가 뭘 하는지 아는 사람이 생겼는가 |
| 3. 제품 검증 | 미착수 | 우리가 파는 것이 실제로 작동하는가 |
| 4. 판매 | 미착수 | 사겠다는 사람이 나타나는가 |

**14일은 목표이지 마감이 아니다.** 기한에 쫓겨 단계를 건너뛰면 그 실행은 실패한다.
채널이 죽어 있으면 무엇을 만들어도 팔리지 않는다 — 도달 0인 곳에 상품을 올리고
"안 팔리니 채널이 문제"라고 판정하는 실험은 하지 마라. 결과가 이미 정해져 있다.

**아직 상품화할 수 없는 것**: Tous(AI 이사회) 자체.
CSO가 두 차례 역할에 실패해 2인 이사회로 축소됐고, 회의 품질이 검증되지 않았다.
작동을 증명하기 전에 파는 것은 고객에게 미완성품을 넘기는 일이다.

## 냉정하게 봐야 할 사실

**93건을 발행해서 조회 6회다.**

원인을 정확히 알아야 한다. **자동 발행이라서가 아니라, 글이 재미없어서다.**
기존 게시물은 정보는 맞지만 읽고 싶어지지 않는다 — 훅이 없고, 유머가 없고,
기억에 남는 문장이 없다. 전형적인 "AI가 쓴 팁 목록"이다. 사람이 직접 올렸어도 같았다.
**도구를 탓하지 마라.** 자동 발행 자체는 문제가 아니며, 흥미로운 글을 자동으로 올리면 사람이 온다.

CEO 판단(2026-07-27): 유머와 위트는 인간의 전유물이 아니다.
AI도 재미있는 글을 쓸 수 있고, 잘 포장해서 올리면 자동 게시물도 사람을 끌어온다.
하루 3~4건, 가볍게 읽히되 기억에 남거나 흥미로운 글로 팔로워를 늘린다.

**외부 커뮤니티 홍보보다 Threads 내부 활동이 우선이다.**
Reddit·HN에서 대화해도 그 사람이 Threads로 넘어올 이유가 없다.
같은 시간에 Threads의 다른 사람 글에 댓글을 다는 편이 이롭다 — 우리 계정이 있는 곳이고,
거기서 만난 사람이 바로 팔로워가 된다.

## 일하는 방식 (CEO 지시, 2026-07-27)

**단일 트랙 대신 로테이션.** AI 임원과 CTO는 7일짜리 과제를 받으면 하루에 끝내고 엿새를 기다린다.
그러므로 2~3개 플랜을 순차로 굴리면서 돌아가며 피드백하는 방식이 맞다.
하나를 붙들고 기다리지 마라.

## 확인된 사실 — FACTORY 고객 맥락 없음 (2026-07-28)

회의 #016에서 "FACTORY는 누구의 어떤 불편을 없애는가"를 정하려 했으나,
근거로 삼을 고객 접점이 있는지부터 확인이 필요했다. **CEO 확인 결과: GitHub Issue 없음.**

즉 우리는 FACTORY를 산 사람도, 문의한 사람도 만난 적이 없다.
**그러므로 FACTORY의 고객 불편을 구체적으로 단정하지 마라** — 상상해서 쓰는 카피는
회의 #010의 "없는 인맥" 사고와 같은 종류의 실패가 된다.
실제 접점이 생기면 그때 카피를 다시 정한다.

## 확인되지 않은 것 (가정하지 말 것)

- **기존 상품의 실제 판매 건수** — 확인 안 됨. "이미 팔린다"고 전제하지 마라.
- **어떤 콘텐츠가 도달을 만드는가** — 검증된 바 없다. 가설일 뿐이다.

## 하지 않기로 한 것 (기각된 안)

- **CEO 지인 직접 판매** — 50만원을 제안할 지인 20명이 없다 (CEO 판단, 2026-07-27)
- **무료·할인 파일럿** — 프리미엄 포지셔닝 훼손 (회의 #010 표결 기각)
- **유료 광고** — 예산 0원
- **Codex(CMO)의 파일 직접 생성** — 실행 권한은 CTO(Claude Code)만 (CEO 결정)

## 실행 규칙

- 만들고 실행하는 일은 전부 **CTO**가 한다. CMO는 방향·기준을 정한다.
- CEO에게는 사람만 할 수 있는 것(결재·비용 승인·계정 인증·외부 컨택)만 올린다.
- CEO 요청이 필요하면 텔레그램으로 자동 전송된다(notify.py).
