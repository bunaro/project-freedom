## 확정된 이름

**회사명은 bunaro(버나로)다.**

**뜻**: "아직 없는 본류를 만든다."
business가 아니라, 아직 정해지지 않은 흐름을 회사가 직접 만들어가는 본류.
원래는 뜻 없는 조어였고 서사는 확정 후 붙였다 — 실제 브랜드가 그렇게 한다.

| 층위 | 이름 | 쓰는 곳 |
|---|---|---|
| 회사 | **bunaro** | 법인·도메인·GitHub 조직·패키지 |
| 창립 서사·IP | **Project Freedom** | 공개 기록·연재·콘텐츠 |
| 제품 | **Tous** | AI Company Operating System |
| 제품 | **Factory** | AI 영상 자동화 도구 |

## 레지스트리별 사용명 (2026-07-29 실측)

**전부 `bunaro` 하나로 통일한다.** 우회가 필요한 곳이 없다.

| 곳 | 상태 |
|---|---|
| **bunaro.ai** | 비어 있음 — **1차 도메인**, CEO 결제 필요 |
| bunaro.io · bunaro.co | 비어 있음 — 확보 권장 |
| GitHub 조직 | 비어 있음 |
| npm · PyPI · Docker Hub | 비어 있음 |
| bunaro.com | **선점됨** — 1차를 .ai로 고정해 회피(회의 #019) |

**.com을 포기한 근거**: 조어 80개를 전수 검증한 결과 **.com이 비어 있는 후보가 0개**였다.
발음 가능한 5~6글자 조합은 도메인 투자자가 이미 전부 선점했다.
.com을 필수로 두면 어떤 새 이름도 통과할 수 없다 — 조건 자체가 틀렸다.

---

## 새 이름을 만들 때

제품이나 저장소 이름에 회사명을 접두사로 붙이지 않는다.
`bunaro-tous`가 아니라 `tous`다 — 조직 아래 있으면 소속이 이미 드러난다.

예외는 전역 네임스페이스를 쓰는 곳이다. npm·PyPI에서는 `@bunaro/tous` 형태의 스코프를 쓴다.

---

## 이름을 정할 때 반드시 확인할 것

`tous/namecheck2.py`로 **다섯 곳을 한 번에** 본다 — 도메인 4종, GitHub, npm, PyPI, Docker Hub.

기존 `namecheck.py`는 도메인과 웹 검색만 봐서 Kaelun 사고를 막지 못했다.
Kaelun은 그 검증을 통과했으나 GitHub·Docker Hub에서 막혀 폐기됐다(회의 #017 → #019).
