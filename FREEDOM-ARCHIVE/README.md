# Freedom Archive — 프로젝트 기록

**Story와 Archive를 한 세트로 남긴다.** 같은 사건을 두 방식으로 기록하는 것이다.

| | 무엇을 담나 | 읽는 사람 |
|---|---|---|
| **[Story](STORY/)** (EP.N) | 사람들이 읽는 이야기 — 감정·대화·흐름 | 외부 독자 |
| **[Archive](ARCHIVE/)** (#NNN) | 실제 있었던 일의 공식 기록 — 결정·근거·의미 | 나중에 이 회사를 추적할 사람 |
| **[Source](SOURCE/)** | **1차 사료** — 그날 실제로 작성된 문서 원문 | 사실을 확인해야 할 사람 |

**Source가 최우선이다.** Story와 Archive는 나중에 쓴 것이라 기억에 의존하지만,
Source는 그날 남은 물건이다. 셋이 어긋나면 Source를 따른다.

### CTO 사실 보완

CMO가 쓴 Archive를 CTO가 사료와 대조해 보완한다.
**원문은 절대 고치지 않는다.** 문서 아래에 `# CTO 사실 보완` 섹션을 따로 붙이고,
출처를 밝힌 뒤 세 가지를 적는다 — **확정된 사실 / 복원본이 놓친 것 / 그 뒤 어떻게 됐나.**

이렇게 나누는 이유는 저자를 지키기 위해서다. CMO의 기록은 그날의 시선이고,
CTO의 보완은 나중에 확인된 사실이다. 둘을 섞으면 누가 무엇을 알았는지가 사라진다.

**작성은 ChatGPT(CMO)가 하고, 저장·관리는 Claude(CTO)가 한다.**
CMO가 초안을 내면 CTO가 문서로 편입하고 색인을 갱신한다.

몇 달 뒤 Archive를 읽으면 **왜 이 회사가 이렇게 됐는지**를 이해할 수 있고,
Log를 보면 **실제로 무엇이 구현됐는지**를 추적할 수 있다.

## 작성 원칙

**하나, 요약하지 않는다.** 한 줄로 끝낼 수 있는 사건도 그날의 흐름을 살린다.

**둘, 실제 대화를 살린다.** "미쳤다…", "잠깐…" 같은 말투가 분위기를 만든다.

**셋, 왜 그렇게 됐는지를 기록한다.** 결과보다 논쟁이 중요하다.
누가 어떤 의견을 냈고, 무엇이 반박당했고, 어느 문장에서 방향이 바뀌었는지.

**넷, 실패를 그대로 남긴다.** 미화하지 않는다.
Claude가 엉뚱한 결정을 내리면 그대로, ChatGPT가 반박하면 그대로,
대표가 화를 내면 그것도 그대로 쓴다.

**다섯, AI도 캐릭터로 기록한다.** Claude는 구조를 만들려 하고,
ChatGPT는 브랜드와 서사를 만들려 한다. 둘이 부딪히며 새 아이디어가 나온다.

**재배치 기록(2026-07-28)**: EP.3(7/22)이 EP.1·2(7/24)보다 앞선 사건이라
번호를 시간순으로 다시 매겼다. 외부 발행 전이라 혼선이 없다.
**발행한 뒤에는 번호를 바꾸지 않는다** — 독자가 길을 잃기 때문이다.

**예정**: EP.6 임원이 무너지다(7/26~27, Gemini·Copilot 이탈 → 2인 이사회) /
EP.7 없는 인맥으로 가결하다(7/27) / EP.8 조회수 6(7/27~28)

**날짜 규칙**: EP.0은 프롤로그라 월 단위로만 적는다.
